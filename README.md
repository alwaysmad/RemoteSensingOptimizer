# Remote Sensing Optimizer (RSO) & SVK Engine

A high-performance C++20 Vulkan compute and scientific simulation platform for satellite constellation observation and orbital coverage optimization.

---

## Prerequisites

- **C++ Compiler:** GCC 13+ (or Clang 17+) supporting C++20.
  - On AlmaLinux / RHEL 9:
    ```bash
    source /opt/rh/gcc-toolset-13/enable
    ```
- **Vulkan SDK:** System package installed (headers, loader, and validation layers).
- **Slang Shader Compiler:** Detected on `PATH` or automatically fetched via CMake (`v2026.18.3`).
- **CMake & Build Tools:** CMake 3.24+ and `ninja` or `make`.

## Code Quality & Development Tooling

### 1. Code Formatting (`clang-format`)
The project uses `.clang-format` (LLVM base style, 4-space tabs, 120-column limit) to maintain uniform formatting across all code:

```bash
clang-format -i $(find src -name '*.cpp' -o -name '*.hpp')
```

### 2. Static Analysis & Linting (`clang-tidy`)
The project configuration in `.clang-tidy` enforces Modern C++20, Bugprone, Performance, and Readability rules while restricting checks strictly to project code (`src/(engine|rso|triangle)/`) and ignoring third-party dependencies (`_deps/`).

Requires `compile_commands.json` generated by CMake (`CMAKE_EXPORT_COMPILE_COMMANDS=ON` is enabled by default):

```bash
# Check a single file:
clang-tidy -p build src/rso/Application.cpp

# Check all translation units:
clang-tidy -p build $(find src -name '*.cpp')
```

### 3. Include Management & PCH Strategy

The codebase adheres to the **Self-Contained Includes (IWYU - Include What You Use)** philosophy coupled with **Precompiled Headers (PCH)** for compilation speed:

- **Self-Contained Files:** Every `.hpp` and `.cpp` file must explicitly `#include` all symbols and types it directly uses (STL headers, GLM, Vulkan, internal modules). No file should implicitly rely on transitive includes.
- **PCH for Build Acceleration:** Standard library components (`<vector>`, `<algorithm>`, `<cmath>`, etc.), Vulkan RAII headers, and GLM are added to `SVK_PCH_HEADERS` via `target_precompile_headers`. PCH acts strictly as a **compiler performance accelerator**, not a semantic substitute for explicit includes.

#### Auditing Includes with Clang-Tidy (`misc-include-cleaner`)
Clang-Tidy includes a built-in include cleaner based on LLVM's `include-cleaner` engine that inspects AST symbol usage against `#include` directives:

```bash
# Ensure compiler environment is loaded (AlmaLinux / RHEL 9):
source /opt/rh/gcc-toolset-13/enable

# Audit a single file (reports unused includes and missing direct includes):
clang-tidy -p build -checks='-*,misc-include-cleaner' src/rso/Application.cpp

# Audit all project translation units:
clang-tidy -p build -checks='-*,misc-include-cleaner' $(find src -name '*.cpp')

# Filter to display ONLY truly unused includes across the codebase:
clang-tidy -p build -checks='-*,misc-include-cleaner' $(find src -name '*.cpp') 2>&1 \
  | grep "is not used directly" | sort -u
```

#### Auditing Includes with Dedicated IWYU (`iwyu_tool.py`)
If `include-what-you-use` and `iwyu_tool.py` are installed:

```bash
# Run IWYU across all translation units defined in compile_commands.json:
iwyu_tool.py -p build -- -Xiwyu --no_fwd_decls > iwyu.log

# Inspect the suggestions:
less iwyu.log

# Automatically apply the suggested include edits (from the IWYU toolkit):
fix_includes.py < iwyu.log
```

#### Verifying Independence from PCH
To ensure no file has hidden dependencies on the precompiled header, run a build with PCH disabled:

```bash
cmake -B build_nopch -DCMAKE_DISABLE_PRECOMPILE_HEADERS=ON
cmake --build build_nopch -j$(nproc)
```

## Build Configurations

### 1. Debug
Enables Vulkan validation layers, AddressSanitizer (ASan), and UndefinedBehaviorSanitizer (UBSan) with zero optimization:

```bash
cmake -B build_debug -DCMAKE_BUILD_TYPE=Debug
cmake --build build_debug -j$(nproc)

# Run interactive or headless
./build_debug/bin/rso
./build_debug/bin/rso_headless
```

---

### 2. Release
Standard production build with high optimization (`-O3`), native CPU architecture targeting (`-march=native`), Link-Time Optimization (LTO), and validation layers disabled:

```bash
cmake -B build_release -DCMAKE_BUILD_TYPE=Release
cmake --build build_release -j$(nproc)

# Run
./build_release/bin/rso
```

---

### 3. Bench (Maximum Aggression)
Designed strictly for performance measurement. Adds aggressive loop unrolling and `-ffast-math`:

> [!WARNING]
> `-ffast-math` breaks strict IEEE 754 compliance (reassociation, no-NaN/Inf assumptions). Orbital mechanics calculations (SGP4, sun vectors) may produce subtle numerical differences. **Use only for timing and throughput measurement, never for simulation correctness validation.**

```bash
cmake -B build_bench -DCMAKE_BUILD_TYPE=Bench
cmake --build build_bench -j$(nproc)

# Run benchmark
./build_bench/bin/rso_headless
```

---

### 4. RelWithDebInfo (Profiling)
Optimized build (`-O2`) preserving debug symbols (`-g`) and frame pointers (`-fno-omit-frame-pointer`). Ideal for sampling with profilers like `perf`:

```bash
cmake -B build_reldbg -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build_reldbg -j$(nproc)

# Profile with Linux perf
perf record ./build_reldbg/bin/rso_headless
perf report
```

## Profile-Guided Optimization (PGO) Workflow

> **Compiler:** GCC &bull; **Build Type:** `Bench`

```bash
# Step 1: Build instrumented binary
cmake -B build_pgo_gen -DCMAKE_BUILD_TYPE=Bench -DENABLE_PGO_GENERATE=ON
cmake --build build_pgo_gen -j$(nproc)

# Step 2: Run workload to generate profile data (.gcda files)
./build_pgo_gen/bin/rso_headless

# Step 3: Rebuild using collected profile feedback
cmake -B build_pgo -DCMAKE_BUILD_TYPE=Bench -DENABLE_PGO_USE=ON
cmake --build build_pgo -j$(nproc)
```

## CMake Configuration Options

Configure these options by passing `-D<OPTION>=<VALUE>` to CMake:

### Optimization & Sanitizers

| Option | Values | Default | Description |
| :--- | :---: | :---: | :--- |
| `ENABLE_LTO` | `ON` / `OFF` | `ON` | Link-Time Optimization (applies to `Release` and `Bench` builds). |
| `ENABLE_ASAN` | `ON` / `OFF` | `ON` | AddressSanitizer (`Debug` only). |
| `ENABLE_UBSAN` | `ON` / `OFF` | `ON` | UndefinedBehaviorSanitizer (`Debug` only). |
| `ENABLE_TSAN` | `ON` / `OFF` | `OFF` | ThreadSanitizer (`Debug` only; mutually exclusive with ASan/UBSan). |
| `CMAKE_DISABLE_PRECOMPILE_HEADERS` | `ON` / `OFF` | `OFF` | Disable PCH to audit self-contained includes. |

### Synthetic Constellation Parameters

| Option | Type / Unit | Default | Description |
| :--- | :---: | :---: | :--- |
| `SYNTH_SAT_COUNT` | Integer | `10` | Number of synthetic satellites generated in the test constellation. |
| `SYNTH_RAAN_START` | Degrees (`0`–`360`) | `0` | Starting Right Ascension of the Ascending Node (RAAN). |
| `SYNTH_RAAN_SPAN` | Degrees (`0`–`360`) | `45` | Total RAAN span across the generated constellation planes. |

#### Example: Debug build with ThreadSanitizer and custom constellation size
```bash
cmake -B build_tsan -DCMAKE_BUILD_TYPE=Debug \
  -DENABLE_TSAN=ON \
  -DSYNTH_SAT_COUNT=250 \
  -DSYNTH_RAAN_SPAN=90
cmake --build build_tsan -j$(nproc)
```
